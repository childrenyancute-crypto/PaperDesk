# PaperDesk 第一版实施方案

这是早期设计记录。当前版本的安装、操作和数据分享设置见[使用说明](usage.zh-CN.md)。

日期：2026-11-22。定位：个人使用的 Mac 文献阅读工具，主要阅读英文理论物理和数学物理文献。

## 1. 已选定的路线

第一版采用「原生轻阅读窗口 + 现有本地 Codex 对话 + 本地资料库」。工作名 PaperDesk 可随时更改。

打开 PDF、选区、批注、笔记和分类在阅读窗口完成；文献讨论沿用现有 Codex 聊天。连接采用本地 MCP，意即向 Codex 提供一组可调用的文献工具。

这样可以先复用当前 Codex 环境中的模型选择、可用插件、工具及子 agent。应用本身不另行调用模型或保管模型密钥。是否能在特定 ChatGPT Work 环境使用同一连接，要实际验证该环境的本机工具支持；普通 Chat 不列为第一版验收目标。

Codex 的登录、额度和工具权限继续由 Codex 管理。切换界面不视为获得额外额度，也不保证其他宿主自动继承当前插件。

## 2. 第一版的使用方式

1. 拖入一篇 PDF，阅读器保存一份受管理的副本，并记住阅读位置。
2. 选中文字，或框选一个公式区域；右侧显示准备讨论的摘录、页码和图像预览。
3. 在旁边的 Codex 聊天中提问，例如「解释当前选区里从式 12 到式 13 的步骤」。Codex 调用工具读取固定下来的选区。
4. 继续追问。需要更多材料时，按照阅读窗口设置的范围读取相邻页或指定页。
5. Codex 通过保存工具生成的批注和笔记自动保存到本地，标记为 AI 草稿。用户可以修改或采纳。
6. 点笔记中的来源，回到原文位置。关闭并重新打开后，阅读位置和记录仍在。

第一版的聊天仍位于现有 Codex 中，阅读窗口和 Codex 并排使用。阅读窗口不承诺自动向当前 Codex 聊天发送消息，也不承诺内嵌完整 ChatGPT 界面。

## 3. 界面范围

- 顶部：文献标题、页码、搜索、缩放和导出。
- 中间：PDF。目录与缩略图按需展开。
- 右侧：两个页签「当前选区」「批注与笔记」。面板可收起。
- 资料库：标题、作者、标签、阅读状态、最近阅读；采用简单列表。
- 全文保持英文；讨论与笔记默认中文，原有符号、公式和术语按需要保留。

首个可运行版本以文字选区为先；公式框选在阶段 C 加入。公式图像不经过第三方识别服务，图像是否能被理解取决于 Codex 中所选模型的能力。

## 4. 第一版功能与后续范围

第一版交付：

- PDF 导入、阅读、搜索、文字选区、公式框选和阅读进度恢复。
- Codex 读取当前文献、固定选区、允许范围内的页面文字和公式图像。
- 手动笔记与 AI 笔记，原文位置关联、编辑、采纳和删除。
- 应用内高亮与批注显示，以及导出带标准批注的 PDF 副本。
- 标签、未读／在读／已读状态，以及标题、摘录和笔记的关键词搜索。
- 手动录入文献信息，保存并复制单条 BibTeX；支持导入 Zotero 导出的标准 BibTeX 子集，无法解析的字段保留原文。
- 本地备份及 Markdown／JSON／BibTeX 导出。

后续按实际使用体验加入：

- DOI／arXiv 信息按需补全、多篇文献对照、符号与假设索引。
- 导入完整的已有文献库、PDF 中已有批注的编辑与复杂格式兼容。
- 直接在阅读窗口聊天，以及使用 Codex app-server 的独立对话界面。
- 语义检索、云同步、跨设备访问。

第一版对已经嵌入 PDF 的批注以 PDFKit 可显示的内容为准，不承诺把所有外部阅读器的批注格式完整转换为本应用的笔记。

## 5. 技术选择

- 窗口和交互：SwiftUI，必要处使用 AppKit。
- PDF：Apple PDFKit。负责页面显示、文字选区、坐标和标准 PDF 批注。
- 记录：SQLite，原 PDF 与选区图像保存在普通文件目录。
- 连接：独立的 Swift MCP 小程序，以 stdio 连接 Codex，再通过本机 Unix socket 与阅读应用通信。
- 构建：优先 Swift Package Manager，后续提供可直接打开的 Mac 应用包。

本机通信使用 Unix socket，不对局域网开放端口。阅读应用是数据库的唯一写入方，MCP 小程序负责转发命令。工具需要阅读应用处于运行状态；应用关闭时返回明确的未连接结果。

建议项目结构：

```text
Sources/
  PaperDeskCore/       文献、位置、笔记等公共数据类型
  PaperDeskStorage/    SQLite、数据迁移、备份与导出
  PaperDeskApp/        PDF 阅读窗口与本机命令入口
  PaperDeskMCP/        Codex 的 stdio 工具连接
Tests/
  StorageTests/        保存、恢复、重复请求、备份
  ContextTests/        选区定位、版本与范围限制
  MCPTests/            工具协议及连接错误
docs/
  implementation-plan.md
```

## 6. 资料库如何保存

开发时使用项目内被 Git 忽略的 `.paperdesk-dev/`；正常应用默认使用 `~/Library/Application Support/PaperDesk/Library/`。以后可由用户选择迁移目录。

资料库包含：

- 文献条目：标题、作者、年份、DOI、arXiv ID、引用条目、标签和阅读状态。
- 文献版本：独立版本 ID、PDF 文件摘要、文件位置、arXiv 版本号和页数。
- 选区快照：固定的选区 ID、版本 ID、页面索引、显示页码、页面坐标、摘录和可选图像。
- 笔记和批注：内容、来源选区、人工或 AI 来源、草稿或已采纳状态、创建和修改时间。
- 阅读记录：最后位置、阅读会话和关联的 Codex 会话 ID（能够取得时保存，不作为必需字段）。

文件改名不改变文献身份。不同 arXiv 版本、期刊版分别记录位置；跨版本关联到同一文献条目，但不自动把旧位置套到新文件上。

数据库是笔记的主要记录；Markdown、JSON 和带批注 PDF 是导出形式。原 PDF 副本保留不变，应用内批注从数据库显示。导出 PDF 时生成新文件，避免多个程序同时保存同一份原文。

备份需要包含数据库的一致快照、PDF 和图像。SQLite 使用备份接口或等价的一致性方案，不在数据库打开时只复制主文件。

## 7. Codex 工具连接

第一条完整流程只实现五个工具：

1. `reading_status`：读取当前文献身份、当前页、允许的上下文范围和固定选区 ID；不在此工具返回整篇内容。
2. `get_context`：按选区 ID 返回同一份固定摘录、来源及可选图像。仅文字模式不返回图像。
3. `read_pages`：读取当前文献指定页，受范围和大小限制，返回内容带页码；截断必须明确说明。
4. `save_note`：按来源选区保存 AI 草稿或用户要求的正式笔记；成功返回记录 ID，失败返回原因。
5. `list_notes`：查看当前文献已存记录，供继续阅读、避免重复整理。

随后扩展 `search_library`、`update_note`、`set_tags`、`navigate_to_source` 和引用及 PDF 导出工具。

接口约束：

- 所有内容读取及写入显式绑定文献版本 ID 或固定选区 ID，避免切换文献后写错位置。
- 写入带请求去重标识，重试同一请求不重复创建笔记。
- 修改已有笔记带修订号，遇到人工编辑冲突时保留双方内容并返回冲突。
- 来源坐标来自阅读器，模型不能编造不存在的页码、选区或文献版本。
- 接口使用文献 ID，不接受任意磁盘路径或任意 SQL。
- 输出协议与诊断信息分离，MCP stdout 仅用于协议消息，错误写入 stderr。

自定义连接器的工具清单和默认权限在真正实现并验证后再接入 Codex。此方案不更改已有插件、模型、akey 或登录配置。

## 8. 自动记录的边界

能够可靠自动保存：选区、手动笔记、交给 `save_note` 的 AI 批注和读后整理。

完整对话由 Codex 自己管理。MCP 连接器并不会自动收到每一条聊天消息，因此第一版不宣传完整聊天镜像备份，也不读取或修改 Codex 的内部会话数据库。

通过针对本阅读工作流的使用说明，让 Codex 在完成一段讨论后调用保存工具，并对保存失败明确报告。后续若要保证每条对话都进入个人资料库，再通过独立聊天界面或正式支持的事件接口实现。

默认 AI 内容保存为草稿。采纳动作改变笔记状态，不把模型推导自动当成作者结论。区分作者陈述、AI 补充推导和用户自己的判断。

## 9. 隐私与资料范围

阅读、笔记和关键词搜索在本地完成。应用不自动同步、收集内容统计、请求云端 OCR 或建立云端索引。

用户可以在阅读窗口选择给 AI 使用的范围：选区、当前页／指定邻页、全文。默认选区；私人笔记默认不包含在原文上下文中。范围限制在工具连接中实际执行，不能只靠提示词约束。

工具将内容交给 Codex 后，相关原文、问题和图像会按 Codex 当前模型与账号规则处理；这不属于完全离线阅读。其他插件的数据流由各自工具与授权决定，本应用不对整个 Codex 环境作绝对隐私承诺。

将来按需补全文献信息时，只发送查询用 DOI／arXiv ID，并在界面说明需要联网。原始全文和私人笔记不用于查询引用信息。

## 10. 开发顺序与验收

### 阶段 A：一篇 PDF 的阅读与保存

实现应用启动、PDF 导入、阅读位置恢复、文字选区、手动笔记和 SQLite 保存。

验收：拖入 PDF 后能阅读和选字；笔记能跳回来源；关闭重启后 PDF、笔记和位置保留；重复导入同一文件不生成无提示的重复条目。

### 阶段 B：连接现有 Codex

实现本机通信和五个基础工具，在开发专用配置中验证 MCP 初始化、工具发现及读写，再接入现有桌面环境。

验收：Codex 能读取真实选区、解释并保存一条带来源的笔记；切换文献后旧讨论仍写回原文献；重复保存请求不生成重复记录；应用关闭时显示连接失败而非虚报已保存。

这一阶段完成，才称为第一个可实际试读的版本。

### 阶段 C：公式与批注

实现公式区域框选、图像上下文、应用内高亮、批注编辑和带批注 PDF 导出。笔记保存 LaTeX 原文；数学排版先在 Codex 中使用，阅读器中公式预览作为独立小任务验证后加入。

验收：选中公式能给支持图像的模型提供清晰区域；换缩放比例、跨页选择后仍定位正确；导出的 PDF 可在「预览」看到标准高亮和批注；导出不改写原 PDF。

### 阶段 D：长期使用与引用

实现标签、关键词搜索、BibTeX、笔记导出、备份和恢复。

验收：能按标签和关键词找回旧笔记；引用条目可复制到 `.bib` 文件；从备份恢复后，PDF、图像、来源位置与笔记一致。

## 11. 试读材料与检查重点

先使用自行生成的小 PDF 检查保存和定位，再使用 3–5 篇用户熟悉的英文文献试读。真实文献不进入代码仓库。

材料应覆盖单栏、双栏、密集公式、公式跨页、附录，以及同一文章不同版本。重点检查 PDF 文本提取顺序、上下标、公式图像清晰度、页面旋转、跨页选区、批注往返、笔记冲突和数据恢复。

第一版优先验证「正确读取、正确保存、能够找回」，再改善自动总结和跨文献比较。

## 12. 开工后的任务分工

主 agent 负责方案、模块之间的约定、整合与最终体验检查。边界清晰的实现任务按用户约定交给 Luna max：阅读界面、SQLite 保存、MCP 连接分别指定文件所有权。接口先定，再开展可独立验证的实现，避免多个 agent 同时修改同一模块。

数据库迁移、上下文范围、写入去重和备份恢复使用有实际意义的自动化测试；阅读窗口、选区和批注导出使用真实交互检查。模型的推导解释需要对照原文核验，不将其他 agent 的赞同视为数学正确性的证明。

## 13. 实现依据

- [Codex 本地 MCP 连接与配置](https://learn.chatgpt.com/docs/extend/mcp)：第一版的连接方式。
- [Apple PDFView](https://developer.apple.com/documentation/pdfkit/pdfview)：原生 PDF 显示与选区能力。
- [Codex app-server](https://learn.chatgpt.com/docs/app-server)：后续独立聊天界面的候选，不是第一版前置依赖。
- [Crossref 引用格式转换](https://www.crossref.org/documentation/retrieve-metadata/content-negotiation/)：后续 DOI 信息与 BibTeX 补全。
- [SQLite 备份接口](https://www.sqlite.org/backup.html)：一致性备份的实现依据。

## 14. 本机开工条件实测

2026-11-22 已完成以下小程序验证；验证文件仅写入临时目录，未修改用户配置：

- macOS 26.0，Apple Silicon；Swift 6.4 可用。
- SwiftUI、AppKit、PDFKit、SQLite3 均能直接导入并通过编译。
- PDFKit 能打开本地生成的 PDF 并读出一页文字。
- 系统 SQLite 3.51.0 可创建数据库、建表并插入记录。
- 本机已装 Command Line Tools，可开展命令行原型开发；尚未安装完整 Xcode，Xcode 工程构建和 Archive 尚不可用。后续应用打包、签名与分发流程单独验证，不作为开始写原型的前置条件。
- 当前执行沙箱下，Swift 默认模块缓存路径不可写；开发构建应将模块缓存指定到项目内 `.build/module-cache/` 等可写位置。

已验证的是框架和本地读写可行性；阅读窗口交互、MCP 连接和真实文献试读仍属于后续实现与验收工作。
